
# 内测方案

> 本方案用于项目立项后的 Alpha 内测准备。正式立项前不以 Datawhale 官方项目名义招募。

## 1. 内测目标

验证前四个已完成学习单元是否能够让目标学习者建立“数学对象—工程问题—数值实验”的连接，并定位以下问题：

- 先修知识是否过高；
- 符号、维度和物理意义是否清楚；
- 推导是否存在关键跳步或错误；
- 实验能否复现正文结论；
- Windows、macOS、Linux 的运行说明是否充分；
- 工程陷阱和迁移问题是否真正帮助理解。

## 2. 建议规模与用户画像

首轮建议 12–20 人，至少覆盖：

| 用户类型 | 建议人数 | 重点观察 |
|---|---:|---|
| 本科低年级、无信号处理背景 | 4–6 | 符号与先修知识负担 |
| 研究生、正在阅读相关论文 | 4–6 | 推导深度与参考资料 |
| 音频或传感器工程实践者 | 2–4 | 工程假设和设备陷阱 |
| 机器学习背景转穿戴方向 | 2–4 | 跨领域迁移是否有效 |

## 3. 内测任务

### 任务 A：环境与最小实验

1. 按 README 安装依赖；
2. 运行全部五个 `examples/` 脚本；
3. 记录操作系统、Python 版本、失败步骤和完整报错；
4. 判断每个脚本的输出是否能支持正文结论。

### 任务 B：前四单元学习

依次完成：

1. 多通道复数向量与 Hermitian 结构；
2. 协方差矩阵、二次型与 MVDR；
3. 特征分解、SVD 与低秩结构；
4. 平稳性、自相关与 PSD。

每单元记录：

- 阅读时间；
- 第一个无法独立理解的位置；
- 最有帮助的工程例子；
- 是否能完成迁移问题；
- 仍然缺失的图、推导或实验。

### 任务 C：参数改动

至少选择一个实验，修改关键参数并解释变化：

- MVDR：快拍数、对角加载量或阵列通道数；
- 低秩去噪：真实秩、噪声强度或保留秩；
- PSD：分段长度、重叠或前后半段噪声强度；
- 正则化融合：正则系数；
- 跨用户评测：用户偏移强度。

## 4. Issue 反馈格式

每个独立问题提交一个 Issue，标题建议：

```text
[内测][单元编号] 简短问题描述
```

Issue 至少包含：

- 文件和小节；
- 当前表述或运行结果；
- 预期理解或预期结果；
- 操作系统、Python 版本（代码问题）；
- 是否阻断继续学习；
- 可选的修改建议。

## 5. 结束问卷

采用 1–5 分量表并保留开放题：

1. 我能解释本项目与普通数学教材的差异；
2. 我能把核心符号对应到真实传感器；
3. 推导步骤足以让我独立复现；
4. 数值实验帮助我验证了公式；
5. 工程陷阱改变了我对理想模型的理解；
6. 导航、公式和代码在我的设备上可用；
7. 我愿意继续完成后四个单元；
8. 哪一处最容易放弃？
9. 哪个概念仍需要图示或动画？
10. 如果只能优先修复一个问题，应该是什么？

## 6. 验收标准

满足以下条件后结束首轮内测：

- 至少 10 名内测者完成前四单元中的 3 个；
- 至少 8 名内测者运行全部五个实验；
- 所有阻断学习的问题均已关闭或有明确修复计划；
- 公式、代码和链接的高优先级错误全部修复；
- 问卷中“能够连接数学与工程问题”的平均得分不低于 4/5；
- 形成公开的内测复盘和 Beta 修订清单。

## 7. 数据与隐私

内测不收集健康数据、原始传感器数据或不必要的个人信息。公开 Issue 中不得提交访问令牌、设备序列号、真实健康记录或可识别个人身份的数据。
